# 공통 히어로 장면

2026-09-27. 사용자 요청에 따라 기존 설계의 데스크톱/모바일 연출 분기를 대체한다.

01–06은 같은 데이터 모델, Canvas, 장면 진행값을 사용한다. 글자와 버튼은 HTML이며 화면 전체를 축소하지 않는다. Container Queries로 배치를 결정하고, 좁은 CASE 그림은 노드 번호와 설명을 연결한다. 선순환 고리는 좁은 화면에서도 원형과 이름을 유지한다.

## 스크롤과 크기 변경

`story/layout.ts`는 브라우저 기본 스크롤을 장면 값 0–5와 각 장면의 읽기 위치로 변환한다. 장면이 `100svh` 무대보다 높으면 그 차이만큼 페이지 스크롤 공간을 추가한다. 먼저 장면 아래쪽을 읽고, 다음 화면 길이 동안 다음 장면으로 전환한다. 중첩 스크롤 영역이나 터치 입력 가로채기는 없다.

ResizeObserver는 무대, 장면, 조작 영역을 관찰한다. 크기가 바뀌면 현재 장면의 진행률과 읽기 비율을 새 스크롤 구간에 대응시킨다. 이야기 아래에 있는 사용자는 이야기 높이 변화만큼 보정해 같은 본문 위치를 유지한다.

`story/enhance.ts`는 같은 진행값을 받아 글과 그림을 표시한다. DOM의 최종 배치를 측정하고 읽기 이동량을 반영해 Canvas 입자가 기록 행·CASE·그래프·고리의 실제 위치에 맞춰 도착한다. 고리는 CASE 그림과 별도의 좌표 매핑을 갖는다. 창 너비에 따른 연출 엔진 재생성은 없다.

기존 GSAP의 빈 진행 타임라인과 Lenis 보간은 브라우저 기본 스크롤 및 한 번의 requestAnimationFrame 갱신으로 대체했다. 독립적인 진행 막대에만 CSS Scroll-driven Animations를 점진적으로 적용한다. 지원하지 않는 브라우저는 동일한 막대를 JS 진행값으로 표시한다.

## 읽기와 성능

- 움직임 줄이기 또는 JS 없음: 같은 내용과 SVG를 일반 문서로 표시한다.
- 렌더러 로드 실패: 기본 스크롤과 장면 이동, SVG를 유지한다.
- 키보드 초점이 다른 장면이나 장면 아래쪽으로 이동하면 해당 내용을 드러낸다.
- 실제 누르는 곳은 최소 44px. 모바일에서도 모든 글과 증빙 링크에 접근할 수 있다.
- 수집 패널은 그림 칸이 좁으면 세 행, 넓으면 다섯 행을 보여 준다.
- Canvas는 실제 그리기 비용을 120회 단위로 관찰한다. 평균 8ms 초과 시 해상도를 1배로, 자동 움직임을 최대 30fps로 낮추고 WebGL 배경의 자동 움직임을 멈춘다. 데이터 입자와 스크롤 전환은 유지한다.
- 숨겨진 탭과 화면 밖에서는 자동 움직임을 멈춘다. Worker는 성능 측정으로 필요성이 확인될 때 별도로 검토한다.

## 검증 범위

`tests/story.spec.ts`는 네 언어의 여섯 장면, 폰·태블릿·데스크톱, 1024/1023px 등의 경계 리사이즈, 긴 장면의 키보드 접근, JS 없는 문서를 확인한다. 기존 반응형·접근성·동작 테스트도 함께 실행한다.

실제 iOS 기기의 주소창 변화, 저전력 모드, 핀치 확대 성능은 데스크톱 Chromium 검증만으로 보장할 수 없으며 실기기 확인 대상이다.
